# Read-only launch metrics feed

`GET https://ipurposesoul.com/api/admin/launch-metrics-feed`

Authenticate with `Authorization: Bearer <your configured token>`. Tokens in
URLs, cookies, or request bodies are not accepted. Missing/incorrect tokens,
including an unset server token, return HTTP 401. Database failures return 503.
Responses are private and non-cacheable.

The JSON response is `{ "count": 0, "snapshots": [] }` when empty. Otherwise,
`snapshots` contains up to 52 existing `analytics_weekly` documents, ordered by
`weekEnding` descending, with `schemaVersion`, `weekStart`, `weekEnding`,
`computedAt`, `reportingTimezone`, `property`, `counts`, `byPlatform`, and `rates`.
Values are returned as stored, including zero counts and null rates. Reading the
feed does not run analytics queries, compute new weeks, or write to Firestore.

## Production setup

In Vercel → `ipurpose-next` → Settings → Environment Variables, create:

- Name: `LAUNCH_METRICS_FEED_TOKEN` (no `NEXT_PUBLIC_` prefix).
- Value: a unique, cryptographically random secret generated and saved by the
  owner, for example 64 random hexadecimal characters (32 random bytes).
  Do not use the literal example text, the test fixture, an existing Firebase
  credential, or an existing Google/Vercel token. No production token is supplied
  or generated by this change.
- Environment: **Production** only. Mark the variable **Sensitive**.

Configure the same secret in the consuming client's server-side Bearer/API-key
authentication setting. Do not paste it into a chat, embed it in a public URL,
commit it, or put it in browser JavaScript. Anyone holding this token can read
these aggregate reports. Save the variable before deploying this route; rotate
it by updating both Vercel and the client's credential and redeploying.

The endpoint alone does not configure a ChatGPT connection. The consumer must
support HTTPS GET requests with a privately stored Authorization header; opening
the URL in an ordinary browser without that header will correctly return 401.

## Focused tests

With the repository dependencies installed:

`node --test tests/launch-metrics-feed.test.cjs`

These tests execute the actual route with a read-only Firestore double and a
test-only environment token. They do not access production or create a secret.
